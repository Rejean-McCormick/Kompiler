# Security and Trust Model

## Threat model

Kompiler assumes the Query Plan may be generated by an LLM and is therefore untrusted structured input. It also assumes Kristal repositories may contain files that are data, scripts, or documentation but are not automatically trusted executables.

Threats include:

- command injection;
- path traversal;
- malicious adapter output;
- resource exhaustion;
- capability spoofing;
- stale-source cache reuse;
- provenance stripping;
- semantic downgrade/coercion;
- accidental network exfiltration;
- arbitrary execution of repository scripts discovered at runtime.

## Core defenses

### No arbitrary shell

Query Plans cannot supply executable commands. Subprocess adapters use fixed allowlisted executables and argument vectors.

### Explicit adapters

Kompiler never scans a Kristal and executes every script it finds. An administrator installs/configures an adapter.

### Root confinement

Adapter file access is confined to configured roots plus explicitly approved cache directories. Resolved paths MUST be checked after symlink resolution according to platform policy.

### Network default deny

Core runtime requires no network. An adapter that needs network access must advertise this and be enabled under explicit configuration.

### Resource caps

Timeout, output bytes, item counts, join sizes, and parallelism are bounded.

### Schema-first output

Adapter output is parsed and validated before it enters the compiler.

### Provenance retention

Normalization cannot silently strip epistemic/status fields required to interpret source material.

## Trust layers

Kompiler distinguishes:

```text
protocol validity
adapter trust
source integrity
source epistemic validation
source authority recognition
reader/view visibility
```

Passing one layer never implies passing another.

## Secrets

The core protocol MUST NOT include secrets. Adapter credentials, if needed, live in OS credential storage or environment/config indirection and are never serialized into Context Packs.


## Standard contract trust

The configured Kristal Standard root is treated as a trusted local contract dependency, not as executable source. Kompiler verifies the pinned `contracts/contract-set.json` SHA-256 before using schemas. A mismatched release fails closed with `KRISTAL_STANDARD_MISMATCH`.
